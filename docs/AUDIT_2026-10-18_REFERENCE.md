## 已确认的问题与修复要求

| 问题 | 修复后应满足的行为 |
| --- | --- |
| `finish_reason=length` 的非空文本被当成成功，截断调用仍可能执行 | 主 Agent 与子任务先拒绝截断，返回 `output_truncated`；保留部分证据，不发布成功 final |
| 提供商支持的 `finish_reason=content_filter` 也可能把部分文本或调用当成成功 | 在相同执行边界返回独立的 `output_filtered`，不执行调用、不自动重试，并在界面解释过滤失败 |
| 首步连续空回复误报步数用尽 | 空回复用 `empty_response`，真正耗尽步数用 `step_limit` |
| 团队循环耗尽后用最后一条工具观察完成工作项 | 必须有明确且非空的模型 final；工具错误后最终恢复成功仍然允许 |
| Task runner 把捕获的错误或步数耗尽字符串作为完成结果 | 同步和后台失败都交由现有错误与持久化通道处理 |
| 前后台 Task 只保留失败消息，丢失可供程序判断的模型错误分类 | 在现有结果上新增安全的 `kind/retryable` 元数据，并让 TaskOutput 从磁盘取回相同分类；不公开部分模型或工具原文 |
| 工具执行后遇到网络错误，整个工作项可能重放 | 已进入工具回合后停止自动整项重试，避免重复副作用 |
| 后台 runner 的异常被误认成签名检查失败，触发再次调用 | 在执行前单独判断调用签名；实际调用至多一次，异常持久化为失败 |
| 派生注册表复用父工具实例，再覆盖权限 gate | 仅复制工具绑定；父实例、交互 broker 和工作区绑定不被子任务修改 |
| 队友拿到父 Agent 的交互、计划或工作区控制 | 子任务排除这些父会话控制，保留自己的工具过滤规则 |
| 队友继承审批、删除、派发等团队控制，通用消息还允许声明发送者 | 不向子任务继承这些父级控制；以后开放消息需先绑定真实队友身份和允许的协议类型 |
| 父级控制换用别名后绕过名称过滤 | 控制工具声明类级能力标记，别名仍受同一边界约束 |
| 无效参数声明被静默转换为空 schema | 无效声明不展示、不绑定、不执行；合法空参数和 MCP schema 形式保持可用 |
| 子任务直接调用适配器，绕过动态发现、schema 和执行快照 | 每次模型调用前捕获最新 schema 快照，工具调用统一经过 Registry |
| 派生注册表丢失 hosted/sandbox/发现限制 | 保留能力限制和实时撤销判断；共享 MCP 传输仍由父拥有 |
| 关闭延迟工具发现时，已派生子任务不受父会话后来进入的计划模式约束 | 强制规划权限独立于可选发现功能，已有快照也不能继续写入；只读工具仍可用 |
| 开启延迟发现后，子任务错误继承主 Agent 的纯委派工具清单 | 主 Agent 保持只编排，工作子任务仍可执行获准读写，同时遵守规划、发现及其他能力限制 |
| 在读取 MCP 权威 schema 前调用旧参数转换，误拒合法可空类型及空属性名 | 优先验证并保留完整权威 schema，旧参数校验只用于旧接口；无效声明和外部引用继续拒绝 |
| Web 开发依赖存在 14 项审计发现 | 升级兼容的构建依赖，保留现有页面样式，通过完整与运行时依赖审计 |
| Tailwind 升级后 CSS 层级、嵌套间距与键盘焦点发生变化 | 保留代码块的工具类优先级、父容器兄弟间距，以及重命名输入和登录输入原本不同的焦点样式 |

另一个假设已被实测否定：Hook 改写参数没有绕过当前强制策略。当前策略检查工具名或预算状态，改写后的参数仍接受 Registry 的 schema 和工具权限检查。23 项相关测试以及真实 Read/Bash 适配器的拒绝探针通过，因此不为这个假设增加重复策略调用。

## 评测与上线边界

`scripts/agent_eval.py` 是无提供商调用的确定性工程评测：检查真实文件副作用、工具拒绝、续接与上下文不变量。它使用脚本化模型输出，不是 SWE-bench、HumanEval 或真实模型任务完成率。`scripts/agent_soak.py` 检查资源与生命周期稳定性，也不衡量模型质量。

有效的模型 final 只能证明运行正常终止；用户目标是否正确完成，还需要任务本身的验收或真实模型评测。当前测试不能给出真实编码任务成功率。

本次修复不构成公网多用户执行上线验收。仍需真实模型/MCP 长会话、隔离与额度、密钥托管、故障恢复、运维备份与回滚演练等证据。Hosted API 目前的元数据服务边界不能被描述为已开放多租户 Agent 执行。生产判定继续参照 [生产审计](AUDIT_2026-10-14_PRODUCTION.md) 和 [v0.1 验收清单](releases/v0.1-readiness.md)。

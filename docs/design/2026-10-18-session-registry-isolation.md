# Web 会话工具隔离修复

目标：修复上线审计中已复现的 A 会话读取 B 工作区文件问题。用户已同意修复，并确认服务器仅清理旧 WodeAgent，保留 CityAIHub。

每个默认 Web Agent 使用独立的 ToolRegistry；工具对象、路径、权限代理、AskUser、发现状态、读缓存和熔断器不跨会话共享。`/api/tools` 只从已初始化会话及显式注入的目录读取元信息，按工具名称去重，不持有或分发其他会话的执行器。未初始化会话保持惰性，不因为目录查询连接 MCP 或初始化模型。

MCP 状态仍按实际客户端实例汇总；同一连接只展示一次，独立连接不假装共享。MCP 连接和引用计数按目标注册表及服务器名管理，失败的启动连接立即回收。每次注册生成独立的代次标记；后台连接先暂存工具，只有当前代次才能发布工具、元信息或待连接记录。最后一次释放在同一把锁内撤销代次、目录及自有工具。已经获准执行连接或发现的工作线程继续持有客户端，结束后才在锁外完成最后一次关闭；同一客户端被新代次复用时不能被旧工作线程关闭。真实客户端操作仍使用自身超时，外层等待超时不丢弃资源所有权。后续服务器配置或构造失败不会跳过已创建连接的引用登记和清理。直接运行 `python -m desktop.service.app` 也复用默认工厂，避免另一个入口重新引入共享注册表。

验收：真实 CodeAgent + 脚本模型的两个默认 Web 会话分别读取和修改各自文件；权限及 AskUser 归属独立；启用延迟工具发现后仍能初始化第二个会话；工具列表可见且查询不构造新 Agent；关闭一个会话不影响另一个。先记录失败，再修复并回归。

服务器清理：先归档旧源码（含未跟踪部署文件）、数据、前端卷、容器元数据与镜像，验证归档与校验和，再删除明确属于旧 WodeAgent 的停止容器、专属网络/卷、专属应用镜像和目录。共享镜像与 CityAIHub 均保留，清理后确认其容器 ID、启动时间与 HTTP 响应没有变化。

边界：用户进一步确认本轮不在该服务器启动我们的服务，以保留 CityAIHub 的资源。本轮不启动新旧 WodeAgent，也不更新或重启 Docker/系统。此修复不把本地可信 Web 变为已验收的公网多租户产品；托管执行、真实身份提供方和生产运维仍按独立验收门禁推进。

运行依赖维护：将 DOMPurify 从 3.4.13 更新至 3.4.17，并同步 lockfile；本地 Web 构建与运行依赖审计通过，既有 Markdown 清洗浏览器回归和全量 Python 回归由该修复提交的 Linux CI 验证。开发依赖的跨主版本迁移不混入本次会话隔离修复。

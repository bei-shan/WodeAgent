# Ridge Code v0.1 release-readiness checklist

**Status: candidate / not yet tagged.** This checklist is evidence-based; a
green Python suite alone does not authorize a public/stable release. Ridge
Code is a local-first, single-operator coding Agent, **not** a multi-tenant
hosted service.

## 1. Offline prerequisite inspection

Start with installed Python runtime dependencies:

```bash
python -m pip install -r requirements.txt
python scripts/v01_preflight.py --target core
python scripts/v01_preflight.py --target web --json
python scripts/v01_preflight.py --target tui --json
```

The script never reads API key values, calls remote model providers or
contacts network services. `--target core` checks Python 3.12+ and required
libraries. `--target web` adds Node 20+, npm and the Web lockfile.
`--target tui` adds Bun 1.4+ and a committed Bun lockfile. Exit status
1 means one or more required checks failed; machine-readable output is
available with `--json`. `--target all` applies all three profiles.

**TUI lockfile:** `tui-v2/bun.lock` is now generated under the same
Bun 1.4.2 version used in the TUI CI and committed with its dependency
integrity information. The TUI workflow uses
`bun install --frozen-lockfile` and rejects accidental lock updates.
This addresses the earlier reproducibility blocker but is not, by itself,
a full v0.1 manual acceptance report.

## 2. Automated release gates

Each candidate commit must pass:

- [ ] Python full regression (`python -m pytest tests/ -q`)
- [ ] API smoke tests, including real thread interruption, prompt wakeups,
  running-session delete conflicts and atomic persistence
- [ ] Web TypeScript build (`npm ci && npm run build`) and Playwright E2E
- [ ] SSE reconnect/Last-Event-ID recovery, cursor expiry and restart rebase;
  verify long-offline clients refresh durable history (see
  [SSE design](../design/2026-10-14-sse-replay-transport.md))
- [ ] TUI Bun typecheck, unit tests and real PTY+HTTP integration tests.
  The TUI workflow now also runs when Python session runtime, Web service
  API, event contracts or shared history persistence change, not only when
  frontend files change
- [ ] Both MCP SDK v2 default and v1 compatibility CI lanes
- [ ] Docker sandbox smoke on a runner with Docker, including stop during a live container command and best-effort daemon cleanup
- [ ] If BoxLite VM is selected for this release, verify actual KVM/HVF VM boot, network disabled, user isolation, read/write workspace mount, stop/timeout and guest cleanup. Fake SDK tests are not equivalent to hardware acceptance. For warm mode additionally validate same-session reuse, idle eviction, concurrency denial and shutdown on real KVM/HVF hardware. E2B cloud VM mode is experimental, single-gateway only, opt-in and cloud-billed; no host-project sync or multi-worker guarantee. Before enabling, demand real E2B provider credential/network/TTL/kill acceptance. The optional Redis atomic capacity and execution-fence ledger prevents parallel claims but is not sufficient for multi-worker ownership/failover; continue to forbid >1 Gateway until complete fencing and reconciliation acceptance. See [E2B phase](../design/2026-10-15-e2b-single-gateway.md).
- [ ] Guest file operations additionally require binary round-trip, symlink, atomic overwrite and cancelled transfer tests. See [guest file protocol](../design/2026-10-15-sandbox-guest-files.md). Secret-bearing writes must use the Docker stdin transport; BoxLite guest file writes remain opt-in behind AGENT_SANDBOX_BOXLITE_STDIN_ENABLED; require hardware-backed native stream, cancellation, symlink and artifact acceptance before a production default. Run `AGENT_BOXLITE_INTEGRATION=1 python -m pytest tests/test_sandbox_boxlite_integration.py -q` on suitable hardware and record the linked evidence.
- [ ] Optional Langfuse/OpenTelemetry SDK contract tests (mock/in-memory)
- [ ] Documentation link integrity

Use the [GitHub Actions page](../../.github/workflows/) and record **run
URLs tied to the exact candidate commit**. Do not treat a prior branch
commit's green checks as equivalent to a release tag's checks.

## 3. Manual acceptance gates (not replaced by CI)

- [ ] Fresh Python 3.12 environment, first-run configuration, and actual
  model provider authentication with non-secret sanitized logs
- [ ] 30+ minute offline resource soak with bounded RSS, FD and thread growth:
  `python scripts/agent_soak.py --duration-seconds 1800 --json`.
  Store [resource-soak evidence](v01-resource-soak.md) for the tagged SHA;
  CI uses only a short mock smoke and does not close this release gate.
  Or launch [Agent resource soak (manual)](../../.github/workflows/agent-resource-soak.yml)
  from GitHub Actions and attach the resulting SHA-bound JSON artifact to
  the release decision. A configured workflow without a passing 30m run
  does **not** satisfy this checkbox.
- [ ] A real 30+ minute Web and OpenTUI session, including disconnect,
  reconnect, tool events, session branching and a process restart
- [ ] Permission modal and AskUser cancellation while waiting; verify no
  delayed approval authorizes work after the cancelled turn
- [ ] OAuth 2.1 HTTP MCP browser authorization, token refresh and revocation
  tested against a real provider (see [OAuth integration](../design/2026-10-14-mcp-http-oauth.md))
- [ ] MCP disconnected server, hanging request, invalid schema, and
  concurrent-agent isolation with a real test MCP server
- [ ] Agent Teams multi-worker task claim, cancellation/restart and
  durable task board state under extended concurrency
- [ ] Container sandbox allow/deny of writes, symlink escape and interruption
  when isolation is explicitly enabled
- [ ] Remote Langfuse/OTLP exporter with operator-configured test credentials;
  verify sanitized metadata arrives with correct parent/child span hierarchy
- [ ] Stop/restart during work without losing last valid conversation data;
  follow backup and rollback procedure. The Web shutdown path now requests
  cooperative cancellation and drains workers for up to a shared two-second
  deadline; uncooperative provider tasks require explicit manual validation.
  See [graceful Web shutdown](../design/2026-10-14-v01-graceful-web-shutdown.md)
- [ ] Tag packaging/install artifacts and their checksums are verified

These gates currently have no completed operator-signed acceptance report.

## 4. Operational/security scope at v0.1

- Local single-operator Web/TUI only. Do not bind unauthenticated service
  to a public interface. `WEB_AUTH_TOKEN` is not full multi-tenant RBAC.
- Docker sandbox is experimental and opt-in. Docker Bash propagates cancellation and a signed ownership reaper now scans expired containers on startup/periodically, but daemon crashes, lost owner keys and unexpected pauses can still leave or disrupt containers. Verify [lease recovery](../design/2026-10-15-docker-lease-reaper.md) with real Docker. The release gate still requires real isolation/cleanup acceptance. Host tool execution is not
  a security boundary. The Windows process tree cancellation path is
  best-effort rather than OS-enforced child teardown.
- Cancelling an MCP client Task is not a transaction rollback on the
  remote server. Real servers can continue mutating state after Stop.
- Local JSONL traces may contain sensitive user content. Remote tracing
  defaults to OFF and exports allowlisted metadata only.
- Cost estimates require operator-supplied model prices; runtime health
  signals are **not** answer-quality scores.
- Portable conversation archives exclude system prompts, secrets, tool
  results and executable state. They are not full Agent backups.
- `.mycodeagent/` and earlier environment variable aliases remain
  compatibility paths and should not be removed in a patch release.

## 5. Release decision and rollback

For a release candidate, freeze dependencies, record the SHA and CI URLs,
close all required gates, and write a dated human acceptance log. Only then
create a versioned `v0.1.0` GitHub release/tag. **This PR is release
preparation, not a claim that the release gates are all complete.**

If a regression appears, stop distribution, roll back to the last
verified commit, and preserve the operator's `.mycodeagent/` state.
Do not delete, rewrite or force-migrate existing snapshots without a
tested backup and restore path.
